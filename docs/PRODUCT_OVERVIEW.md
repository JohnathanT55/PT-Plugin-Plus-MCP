# PT-Plugin-Plus MCP 产品介绍

## 一句话说明

PT-Plugin-Plus MCP 是 PTPP 的可选本机助手服务：它把模型调用和 MCP 工具连接放在独立进程中，PTPP 只负责浏览器里的页面、站点和本地业务操作。

## 为什么单独运行

Chrome Manifest V3 扩展不适合直接运行标准 MCP 的 stdio 服务，也不应该把模型 API Key 长期放在扩展配置中。独立 bridge 让两边职责清楚：

- PTPP 保存站点、下载器和备份等本地数据，并执行用户授权的业务操作；
- MCP 服务保存模型服务配置，负责 AI 请求和 MCP 客户端连接；
- 两者只通过本机、带令牌的 HTTP bridge 通信。

bridge 未启动或被关闭时，PTPP 仍然可以独立工作。AI 入口只在连接成功后显示。

## 与 PTPP 的关系

MCP 不是另一个浏览器插件，也不是 PT-depiler 的产品界面。它是 PTPP 的可选连接层，使用 PTPP 动态注册的 capability；未注册的功能不会被调用。

当前设计优先提供查询、分析和搜索辅助。删除、恢复备份和实际推送下载等高风险操作不会直接交给模型自动执行。

## 数据边界

PTPP 和 MCP 都会限制字段、长度和请求大小，不开放原始 DOM、完整 storage、Cookie、密码、下载器凭据或完整备份内容。模型服务仍可能保存它收到的问题和上下文，因此应选择可信的 OpenAI-compatible 服务，并避免在对话中粘贴凭据。

## 典型使用流程

```text
启动本机 MCP bridge
        ↓
在 PTPP 设置中启用并测试连接
        ↓
AI 浮窗根据当前页面提供建议问题
        ↓
PTPP 执行已注册的查询/搜索能力
        ↓
MCP 将结果交给模型，返回可读回答
```

## 后续方向

后续可以继续增加更多只读数据能力、搜索辅助和明确确认后的操作，但每项能力都必须有清晰的输入输出、权限级别、确认策略和隐私边界。
